## Azure 部署结果（下午）
- 用户要在当前 Azure 账号（jiangyaqi@scivita.life / Azure subscription 1）部署 index.html。
- 原计划 Static Web App，但本沙箱 npm 安装 SWA CLI 反复被 Windows 回收站/杀软拦截自毁（http-proxy-agent dist/index.js 缺失、package.json 被删），且 SWA 部署 REST 端点（/api/deploy、/.api/deploy、SCM 主机）在本环境均不可达（404/000）。
- 改用 App Service ZIP 部署（可靠）：
  - 计划 yth-plan（Windows F1 免费，centralus）
  - Web App yingtanghong-web → https://yingtanghong-web.azurewebsites.net（State: Running）
  - `az webapp deploy --src-path app.zip --type zip` 成功，线上返回 47424 字节，含 Ying Tang Hong / 英唐行投资 / Founded in 1990。
- 关键发现：KXJ 本身就是 hero-static-rg 下的 Static Web App（之前只查 webapp 列表漏看 staticwebapp，误以为在别的账号）。若要部署到 KXJ 的 URL 需走 SWA 部署通道（本环境暂不可行），或用户在 portal 给 KXJ 连 GitHub。
- 已删除无法部署的空 SWA yingtanghong-site；本地临时文件 app.zip/.auth.txt/online_check.html 已清理（.auth.txt 含部署令牌，已删）。
- 经验教训：本环境 Azure 静态站部署优先用 `az webapp deploy`（ZIP），避开 SWA CLI。
